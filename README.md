# MIG 용접 XR 시뮬레이터 — 평판 맞대기 일자 비드

평판 두 장을 맞댄 1G(아래보기) 자세에서 직선 MIG 비드를 놓는 WebXR 트레이너입니다.
빌드 단계가 없습니다. three.js r160은 `vendor/`에 같이 넣어두고 `index.html`의
importmap으로 불러오므로 인터넷 없이도 돌아갑니다 (CDN이 막히면 모듈 그래프가
통째로 죽어서 빈 화면만 남습니다).

## 실행

```bash
npm run serve        # http://localhost:8777/  — PC에서 보기, Quest Link도 이걸로
npm run serve:vr     # https://<내 IP>:8443/   — 퀘스트 무선 접속용
```

의존성 없이 `serve.mjs` 하나로 돕니다 (npm install은 테스트용 three만 받습니다).

`?debug=1`을 붙이면 `window.weldDebug`로 `scene / camera / renderer / seam /
guide / bead / hud / session / desktop`에 접근할 수 있습니다. 헤드셋 없이
콘솔에서 값을 바꿔가며 튜닝할 때 씁니다.

## 조작 (데스크톱)

| 키 | 동작 |
|---|---|
| W / S | 진행 · 후퇴 (운봉) |
| A / D | 좌우 이동 (중심 이탈) |
| Shift | 빠른 이동 (재배치용) |
| Q / E | 아크 길이(토치-모재 거리) |
| ↑ / ↓ | 전진각 (push angle) |
| ← / → | 작업각 (work angle) |
| Space | 트리거 (아크 ON) |
| R | 다시 하기 |

## 조작 (VR)

컨트롤러가 곧 토치입니다. 손의 **위치와 방향 6DoF 전부**가 그대로 들어가므로
운봉 거리·속도·아크 길이·전진각·작업각이 전부 실제 손동작으로 결정됩니다.
키보드처럼 축이 분리돼 있지 않습니다.

| 입력 | 동작 |
|---|---|
| 토치 손 트리거 | 아크 ON (누르고 있는 동안 비드가 쌓임) |
| 반대 손 그립(쥐기) | 작업대를 잡아서 끌기 — 편한 높이·거리로 옮김 |
| `?hand=left` | 왼손잡이 (기본은 오른손) |

토치는 컨트롤러 인덱스가 아니라 런타임이 알려주는 **손(handedness)** 에 붙습니다.
헤드셋마다 인덱스 순서가 달라서입니다.

작업대는 플레이어 앞 42cm, 높이 90cm에 놓입니다. 용접 중(아크 ON)에는 작업대를
못 끕니다 — 끌면 심 좌표가 순간이동해서 말도 안 되는 운봉 속도로 기록됩니다.

### 퀘스트에 무선으로 띄우기

WebXR은 보안 컨텍스트에서만 동작합니다. `localhost`는 예외로 인정되지만
`http://192.168.x.x`는 아니라서, 무선으로 붙으려면 HTTPS가 필요합니다.
`serve.mjs`가 자체 서명 인증서를 만들어 처리합니다.

**1. 방화벽 열기** — PC와 퀘스트가 같은 공유기에 있어도 Windows 방화벽이
먼저 막습니다. 특히 네트워크가 *공용(Public)* 으로 잡혀 있으면 확실히 막힙니다.
**관리자 권한** PowerShell에서 한 번만:

```powershell
New-NetFirewallRule -DisplayName "Welding XR (8443)" -Direction Inbound `
  -Protocol TCP -LocalPort 8443 -Action Allow -Profile Any -RemoteAddress LocalSubnet
```

같은 랜 안에서만 열리므로 네트워크 전체를 사설(Private)로 바꾸는 것보다 안전합니다.
나중에 치울 때는 `Remove-NetFirewallRule -DisplayName "Welding XR (8443)"`.

**2. 서버 켜기**

```bash
npm run serve:vr
```

접속할 주소가 출력됩니다 (`https://192.168.x.x:8443/`).

**3. 퀘스트 브라우저에서 그 주소 열기** — 인증서 경고가 뜨면
**고급(Advanced) → 계속(Proceed)**. 이후로는 보안 컨텍스트로 인정돼
`ENTER VR` 버튼이 살아납니다.

잘 안 될 때:

- PC가 유선, 퀘스트가 Wi-Fi여도 **같은 공유기·같은 대역**이어야 합니다.
  게스트 Wi-Fi는 보통 격리돼 있어 안 됩니다.
- 주소를 `http://`로 치면 안 됩니다. 반드시 `https://`.
- `ENTER VR`이 안 보이면 주소창 자물쇠가 깨져 있어도 상관없지만, 경고 화면을
  실제로 통과했는지 확인하세요.

### Quest Link(유선/Air Link)로 보기

헤드셋을 PC에 연결한 상태라면 HTTPS가 필요 없습니다. PC Chrome에서
`npm run serve` 후 `http://localhost:8777/` 열고 `Enter VR`.

## 가이드 구성

모재 위(레퍼런스 ①):

- **노란 점선 영역** — 허용 용접 구역. 비드 폭보다 넉넉히 패딩을 줘서 남은 여유를 보여줍니다.
- **노란 화살표(셰브런)** — 진행 방향. 커서 앞쪽만 흐르고, 비드 끝을 지나서도 계속 이어져
  다음에 가야 할 방향을 가리킵니다.
- **파란 실선** — 아직 용접하지 않은 남은 경로.
- **파란 원** — 토치가 모재와 맞닿는 현재 접점.

토치 위에 떠다니는 HUD(레퍼런스 ②③), 항상 시점을 향해 빌보딩됩니다:

- **깊이 가이드** — 아크 길이(CTWD). 화살표 끝이 가로대에 닿으면 정상, 가로대를 뚫고
  내려가면 너무 가까움, 위로 물러나면 너무 멈.
- **중앙 가이드** — 십자선 위의 점. 가로축 = 심 중심에서의 좌우 이탈, 세로축 = 전진각 오차.
- **속도 가이드** — 빨강/노랑/초록 다이얼. 바늘이 초록이면 적정 운봉 속도.

## 비드

HUD만 보고 끝나지 않도록, 실제로 놓인 비드가 결과물로 남습니다.

- 천천히 가면 넓고 두껍게 쌓이고, 빨리 가면 가늘게 굶습니다 (적층량 ∝ 1/속도).
- 리플 간격은 고정 아크 주파수에서 생기므로 속도가 빠를수록 늘어납니다.
- 심에서 벗어나면 비드도 토치를 따라 끌려갑니다.
- 자세가 나쁠수록 스패터가 많아지고 비드 색이 어두워집니다.

## 채점

`WeldSession`이 아크가 켜진 시간 중 각 축이 허용 오차 안에 있던 비율을 누적합니다.
총점 = 깊이 30% + 중앙 30% + 속도 25% + 적층률 15%.

기준값(`src/WeldSession.js`에서 조정):

| 항목 | 기준 | 허용 |
|---|---|---|
| 아크 길이 | 10 mm | ±4 mm |
| 중심 이탈 | 0 mm | ±5 mm |
| 전진각 | 15° push | ±18° |
| 운봉 속도 | 10 mm/s | ±6 mm/s |

## 파일

| 경로 | 내용 |
|---|---|
| `main.js` | 씬·모재·토치·입력·메인 루프 |
| `src/WeldSeam.js` | 직선 심 좌표계 (진행 / 법선 / 횡방향) |
| `src/LinearGuide.js` | 모재 위 가이드 (영역·화살표·중심선·접점 원) |
| `src/TorchHud.js` | 토치 위 3종 게이지 (캔버스 → 빌보드 쿼드) |
| `src/WeldBead.js` | 비드 적층 · 용융풀 · 스파크 |
| `src/WeldSession.js` | 측정·판정·채점 |
| `vendor/` | three.js r160 + OrbitControls + VRButton (오프라인 실행용) |
| `legacy/` | 이전 원형 파이프 조인트 가이드 (참고용, 미사용) |
