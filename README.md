# 용접 XR 시뮬레이터

### 추가된 용접 시야와 3D 자세 안내

- **머리 회전 시 안정화**: XR 카메라는 프레임당 한 번 갱신하고, HUD의 관찰 위치는 해당 XR 프레임의 실제 머리 중심에서 읽습니다. 마스크 화면은 좌우 눈별로 따로 캐시하며, VR 해상도 배율은 0.85와 주변부 렌더링 절약 설정을 사용합니다. 실제 Quest에서의 떨림 해소 여부는 실기 확인이 필요합니다.
- **파이프 아래 공간**: 철판을 아래로 220 mm 늘려 전체 높이 390 mm로 만들고 작업대를 내렸습니다. 파이프 중심과 용접선은 유지하며, 파이프 아랫면에서 상판까지 약 273 mm 공간을 확보했습니다. 물리적 토치 충돌 판정은 아직 없습니다.

- **안정화**: VR 중에는 OrbitControls를 멈추고, 손 입력에 약 55 ms 완충을 적용합니다. 머리 추적은 그대로 유지합니다. HUD 위치·방향·수치도 부드럽게 변화하고, 아크가 꺼져 있으면 속도 바늘은 중앙에 놓입니다.
- **입문 허용 범위**: 화면에서 사용하는 세션은 기본 채점 설정보다 약 1.5배 넓은 범위입니다. 파이프는 아크 길이 ±2.4 mm, 좌우 ±3.5 mm, 각도 ±22°, 속도 ±1.8 mm/s입니다. 기존 엄격한 기본값과 회귀 테스트는 유지합니다.
- **고스트**: 실제 토치와 같은 모델로 권장 자세를 표시합니다. 손을 흔드는 위치 대신 실제 용접 진행도를 기준으로 이동하며, 새 획에서는 시작점으로 돌아갑니다.
- **작업실**: 로컬에서 생성한 긁힘·반사 질감의 철판과 파이프, 실제 구멍이 있는 타공 작업대, 밝은 조명과 간단한 공구·선반을 추가했습니다. 외부 이미지나 모델 다운로드는 없습니다.

- **VR 파이프 과제에서 왼손 Y**: G 키와 같은 시범 재생을 켜고 끕니다. 켜거나 끄면 새 세션으로 시작합니다. 시범 중에는 토치가 스스로 움직이며 위빙·아크·획 전환까지 재생됩니다.
- **오른손 B**: VR 조작 안내판을 표시하거나 숨깁니다. 처음 VR에 들어가면 안내판이 보이고, 용접 손 설정에 맞춰 트리거·그립 설명도 바뀝니다.
- 마스크는 각 눈의 화면 밝기를 초록색 단색 명암으로 변환하고 약한 입자감을 더합니다. 토치 HUD 3종과 조작 안내판은 필터 이후에 그려 본래 색을 유지합니다.

- **왼쪽 Quest 컨트롤러 X / 키보드 X**: 어두운 초록색 용접 마스크 필터와 검은 창 테두리를 켜고 끕니다. VR에서는 실제 머리 위치를 유지합니다. PC에서는 작업물 앞의 눈높이 시점으로 옮겼다가 원래 카메라 위치로 돌아옵니다.
- **반투명 초록색 봉과 손잡이**: 현재 위치에서 권장되는 봉 끝 높이와 기울기를 보여줍니다. 노란 공중 화살표는 진행 방향입니다.
- **공중의 초록색 경로**: 권장 봉 끝의 다음 25 mm 경로입니다. 파이프에서는 시범 데이터의 위빙과 높이를 곡면 프레임으로 변환합니다.
- 비드 표면에는 물결에 따른 실제 높낮이와 불규칙한 가장자리, 금속 하이라이트가 추가됩니다. 용접 주변에 남는 작은 금속 알갱이는 자세가 나쁠수록 늘어납니다. 모두 훈련용 시각 표현이며 물리 기반 용융 해석은 아닙니다.
- `npm test`에는 마스크 버튼 전환, 카메라 복원, 곡면 자세, 금속 알갱이 초기화 검증도 포함됩니다. Quest 실기와 화면의 시각적 품질은 별도로 확인해야 합니다.

**헤드셋을 쓰고 용접을 연습하는 웹 프로그램입니다.** 쇠도 가스도 불꽃도 없이,
손을 움직이는 연습만 떼어내서 반복할 수 있게 만들었습니다.

브라우저만 있으면 됩니다. 설치할 것도, 빌드할 것도 없습니다.

## 1. 이게 왜 필요한가

용접은 손기술입니다. 잘된 용접과 망친 용접의 차이는 대부분 **네 가지 손동작**에서
갈립니다.

| 항목 | 쉬운 말로 | 틀리면 |
|---|---|---|
| **아크 길이** | 용접봉 끝을 쇠에서 얼마나 띄우는가 | 붙이면 봉이 들러붙고, 띄우면 불이 꺼지고 바람이 들어간다 |
| **운봉 속도** | 얼마나 빨리 끌고 가는가 | 느리면 쇠가 뚫리고, 빠르면 겉만 붙고 속은 비어 있다 |
| **작업각** | 봉을 좌우 어느 쪽으로 기울였는가 | 한쪽만 녹아 붙고 반대쪽은 안 녹아서 홈이 파인다 |
| **전진각** | 봉을 진행 방향으로 얼마나 눕혔는가 | 녹은 쇳물이 앞으로 흘러 덮으면 그 밑이 안 붙는다 |

실제 용접장에서는 이 네 가지가 **동시에** 틀립니다. 게다가 헬멧 너머로는 눈부신
불빛밖에 안 보여서, 초보자는 자기가 뭘 틀렸는지 알 수가 없습니다.

이 시뮬레이터는 그 네 가지를 **각각 분리해서 실시간으로 보여줍니다.** 지금 너무
빠른지, 봉이 기울었는지, 선에서 벗어났는지를 숫자와 게이지로 알려주고, 끝나면
점수를 매깁니다.

## 2. 지금 할 수 있는 것

두 가지 과제가 들어 있습니다.

| 주소 | 무엇을 용접하나 | 난이도 |
|---|---|---|
| `/index.html` | **평판 맞대기** — 철판 두 장을 나란히 놓고 그 사이를 일자로 한 줄 | 입문 |
| `/pipe.html` | **파이프 전주 필릿** — 벽에 꽂힌 파이프 둘레를 한 바퀴, 두 번에 나눠서 | 실전 |

**평판**은 직선입니다. 자세가 끝까지 똑같아서 손동작만 익히면 됩니다.

**파이프**는 원입니다. 한 바퀴 도는 동안 몸의 자세가 계속 바뀝니다 — 위쪽(12시)은
내려다보며 하고, 옆(3시·9시)은 벽에 쓰는 것처럼 하고, 아래(6시)는 **천장에 대고
거꾸로** 해야 합니다. 그래서 실제 현장에서도 파이프 용접이 자격증의 기준입니다.

## 3. 3분 만에 실행하기

**필요한 것:** Node.js (아무 버전이나 최신), 크롬 브라우저.
헤드셋은 **없어도 됩니다** — 키보드로 전부 됩니다.

```bash
cd welding-xr-demo
npm run serve
```

브라우저에서 `http://localhost:8777/` 을 엽니다.
파이프 쪽을 보려면 `http://localhost:8777/pipe.html`.

> 인터넷 연결이 끊겨 있어도 돌아갑니다. 3D 엔진(three.js)을 `vendor/` 폴더에
> 같이 넣어뒀기 때문입니다.

### 키보드 조작

| 키 | 동작 |
|---|---|
| **Space** | 아크 켜기 (누르고 있는 동안만 용접됨) |
| **W / S** | 앞으로 / 뒤로 — 이게 운봉입니다 |
| **A / D** | 좌우로 — 선에서 벗어나는 방향 |
| **Q / E** | 봉을 쇠에서 띄우기 / 붙이기 (아크 길이) |
| **↑ / ↓** | 전진각 (앞뒤로 눕히기) |
| **← / →** | 작업각 (좌우로 눕히기) |
| **Shift** | 빠르게 이동 (용접 안 하고 자리만 옮길 때) |
| **R** | 처음부터 다시 |
| **G** | **명장 시범 재생** — 잘하는 사람이 어떻게 하는지 그대로 보여줍니다 |

처음이라면 **G부터 눌러보세요.** 속도도, 각도도, 손 떨림의 리듬까지 그대로
재생됩니다. 그걸 보고 따라 하는 게 가장 빠릅니다.

## 4. 화면 읽는 법

### 쇠 위에 그려지는 것

- **노란 점선 영역** — 여기 안에서 용접하라는 구역입니다. 벗어나면 감점.
- **노란 화살표** — 가야 할 방향. 아직 안 한 쪽으로만 흘러갑니다.
- **파란 실선** — 남은 거리. **실제로 용접한 만큼만 줄어듭니다.**
  아크를 안 켜고 토치만 지나가면 선은 그대로 남아 있습니다.
- **파란 원** — 지금 용접되고 있는 지점. 선에서 벗어나면 그 자리에 멈춰서
  속이 빈 채로 깜빡입니다 = "여기로 돌아와라".

### 토치 위에 떠 있는 게이지 3개

항상 내 쪽을 바라보도록 돌아갑니다.

- **깊이 게이지** — 화살표 끝이 가로대에 딱 닿으면 정상. 뚫고 내려가면 너무 붙음,
  위로 뜨면 너무 멈.
- **중앙 게이지** — 십자선 위의 점. 좌우로 벗어나면 가로로, 전진각이 틀리면
  세로로 움직입니다.
- **속도 게이지** — 자동차 계기판처럼 생겼습니다. 바늘이 **초록**이면 적정 속도.

### 뒤에 서 있는 상황판 (파이프 과제)

작업물 뒤에 큰 판이 하나 서 있습니다. 네 가지 수치가 시간에 따라 꺾은선으로
쌓이고, 초록 띠 안에 들어 있으면 잘하고 있는 겁니다. 끝나면 같은 자리에
성적표가 뜹니다.

> VR 헤드셋 안에서는 웹페이지의 글자가 안 보입니다. 그래서 숫자를 전부 3D 물체로
> 만들어 세워둔 것입니다. **헤드셋 안에서 보이는 수치는 이 상황판과 게이지 3개가
> 전부입니다.**

## 5. 쌓이는 비드

게이지만 보다 끝나지 않도록, **실제로 놓인 용접 자국(비드)이 남습니다.**

- 천천히 가면 넓고 두껍게, 빨리 가면 가늘게 쌓입니다.
- 비드 표면의 물결무늬(리플)는 속도가 빠를수록 늘어집니다.
- 선에서 벗어나면 비드도 따라서 휘어집니다.
- 자세가 나쁘면 불똥(스패터)이 튀고 색이 어두워집니다.

끝나고 자기가 놓은 줄을 보면, 점수를 안 봐도 어디서 급했는지 보입니다.

## 6. 점수

아크가 켜져 있던 시간 중 **각 항목이 허용 범위 안에 있던 비율**을 누적합니다.

**평판 (단일 패스)**

| 항목 | 목표 | 허용 | 배점 |
|---|---|---|---|
| 아크 길이 | 10 mm | ±4 mm | 30% |
| 중심 이탈 | 0 mm | ±5 mm | 30% |
| 운봉 속도 | 10 mm/s | ±6 mm/s | 25% |
| 적층률 | — | — | 15% |

**파이프**는 여기에 세 가지가 더 붙고, **획마다 따로** 점수가 나옵니다.

- **작업각 45°** — 필릿 용접의 핵심 측정값
- **이음부** — 두 번째 획이 첫 획 위에 제대로 겹쳤는가
- **진행 방향** — 아래에서 위로 올려 용접했는가

## 7. VR 헤드셋으로 하기

### 케이블/Air Link로 PC에 연결된 경우

그냥 `npm run serve` 하고 PC 크롬에서 `http://localhost:8777/` 연 다음
`ENTER VR`을 누르면 됩니다.

### 퀘스트 단독(무선)으로 접속하는 경우

WebXR은 보안 연결(HTTPS)에서만 동작합니다. 그래서 두 단계가 필요합니다.

**1단계 — 방화벽 열기 (최초 1회만).** **관리자 권한** PowerShell에서:

```powershell
New-NetFirewallRule -DisplayName "Welding XR (8443)" -Direction Inbound `
  -Protocol TCP -LocalPort 8443 -Action Allow -Profile Any -RemoteAddress LocalSubnet
```

같은 공유기 안에서만 열리므로 안전합니다.
나중에 치울 땐 `Remove-NetFirewallRule -DisplayName "Welding XR (8443)"`.

**2단계 — 서버 켜기**

```bash
npm run serve:vr
```

화면에 `https://192.168.x.x:8443/` 같은 주소가 뜹니다. 퀘스트 브라우저에서 그
주소를 열고, 인증서 경고가 뜨면 **고급 → 계속**을 누릅니다.

**안 될 때 확인할 것**

- 주소 앞이 `https://` 인가? (`http://` 는 안 됩니다)
- PC와 퀘스트가 **같은 공유기**인가? 게스트 Wi-Fi는 서로 격리돼서 안 됩니다.
- 관리자 PowerShell에서 방화벽 명령을 정말 실행했는가?

### VR 조작

컨트롤러가 곧 용접봉입니다. 손의 위치와 방향 6축이 전부 그대로 들어가므로,
키보드처럼 축이 나뉘어 있지 않고 **실제 손동작 그대로** 평가됩니다.

| 입력 | 동작 |
|---|---|
| 토치 손 트리거 | 아크 |
| 반대 손 트리거 | 다시 하기 |
| 반대 손 그립(쥐기) | 작업대를 잡아 끌어서 편한 위치로 옮기기 |

왼손잡이는 주소 끝에 `?hand=left`를 붙이세요.
용접 중에는 작업대를 못 옮깁니다 (옮기면 좌표가 순간이동해서 말도 안 되는 속도로
기록됩니다).

### 한 작업대에 두 과제 — `shop.html`

`index.html`과 `pipe.html`은 과제가 하나씩인 페이지라, 바꾸려면 페이지를 다시
열어야 했습니다. 헤드셋에서는 그게 **XR 세션이 끊긴다**는 뜻이고, 결국 기기를 벗고
다시 들어가야 합니다.

`shop.html`은 한 작업대에 둘을 같이 올려둡니다. 왼쪽이 평판 맞대기, 오른쪽이 파이프
필릿입니다. 빈 손 컨트롤러로 작업물을 가리키면 파란 테두리와 이름표가 뜨고, 트리거를
당기면 그 과제로 넘어갑니다 (데스크톱에서는 클릭, 또는 **1**/**2**). 아무것도
다시 로드되지 않으므로 세션이 그대로 유지됩니다.

메뉴 패널이 아니라 작업물을 직접 가리키게 한 이유는, 헤드셋에서 메뉴는 "따로
쳐다봐야 하는 또 하나의 물건"이고 작업대 앞에 서 있다는 느낌을 깨뜨리기 때문입니다.

**과제를 바꿔도 이미 놓은 비드는 남습니다.** 비활성 쪽은 가이드와 HUD만 꺼지고,
용접 결과는 그대로 작업대에 있습니다. 한쪽을 끝내고 다른 쪽을 하다가 돌아와서 자기
비드를 들여다볼 수 있다는 것이, 둘을 한 작업대에 올린 이유입니다.

명장 궤적 재생(**G**, VR은 왼손 Y)도 그대로 씁니다. 파이프 과제에서만 의미가
있으므로 평판을 고른 상태에서 G는 아무 일도 하지 않고, 재생 중에 다른 작업물로
옮기면 재생이 꺼집니다 — 재생은 그것이 기록된 작업물에 속한 것이고, 플래그를 들고
넘어가면 반대쪽에 토치가 없는 채로 남기 때문입니다.

기존 두 페이지는 **그대로 남아 있고 그대로 동작합니다.** `shop.html`은 대체물이
아니라 세 번째 진입점이라, 여기서 문제가 생겨도 검증된 두 과제를 끌고 내려가지
않습니다.

### 용접봉은 쥐어야 붙는다 — 트리거 두 개

컨트롤러 뒤에는 버튼이 둘입니다. 검지 트리거(위)와 그립(아래).

- **그립** = 용접봉을 쥐거나 놓습니다. 놓으면 작업대 위 제자리에 내려놓입니다.
- **그립 + 트리거** = 아크. 둘 다 눌러야 붙습니다.

실제 홀더는 아크가 가기 한참 전부터 손이 이미 감겨 있습니다. 트리거만으로 아크가
붙게 두면 봉이 손 근처에 없어도 용접이 되어 버리는데, 그건 가르치려는 동작 자체를
없애는 것입니다. 쥐는 동작과 치는 동작을 나누면 **손에 쥐었다**는 감각이 생깁니다.

빈 손 그립은 그대로 작업대 끌기이고, 빈 손 트리거는 작업물 선택·서랍·다시하기입니다.

### 조작 안내는 서랍 속에

예전에는 화면 오버레이에 문단 다섯 개와 불릿 한 무더기가 들어 있었습니다. 헤드셋에서
그건 쓸모가 없는 정도가 아니라 해롭습니다 — 용접 마스크 너머로 HTML을 읽을 수 없고,
패스 도중에 키 배열이 궁금해진 훈련생은 볼 곳이 없습니다.

그래서 작업장에서 실제로 설명서가 있는 자리로 옮겼습니다: **작업대 밑 서랍**.
가리키고 트리거를 당기면 서랍이 열리고, 안에 종이 한 장이 들어 있습니다. 종이를
가리키고 한 번 더 당기면 눈앞으로 들어 올려 읽을 수 있고, 다시 당기면 제자리에
돌아갑니다. 서랍을 닫으면 종이도 같이 들어갑니다.

꺼내 주는 대신 **찾게 만든** 것이라, 시작하려는 사람이 설명서를 스크롤해 지나칠
필요가 없습니다. 오버레이에는 이제 "서랍을 열어 보라"는 한 줄과 급할 때 쓸 키 몇 개만
남았습니다.

### 에셋 다시 굽기

`assets/` 안의 파일은 내려받은 것이 아니라 `tools/blender/`의 스크립트가 만든
결과물입니다. 블렌더만 있으면 어디서든 똑같이 재생성됩니다.

```bash
blender -b -P tools/blender/make_env_hdr.py     # 작업장 HDRI (~15초)
blender -b -P tools/blender/bake_bead_maps.py   # 비드 노멀 + AO
```

**환경 프로브가 왜 중요한가.** 연마된 스테인리스는 사실상 거울이라, 보이는 밝기가
곧 "주변에 무엇이 있는가"입니다. 예전에는 색 박스 세 개로 환경을 만들어 썼는데,
반사할 것이 없으니 어떤 텍스처를 붙여도 강판이 회색 플라스틱으로 보였습니다.

그래서 이 방은 밝은 벽·천장에 **넓은 소프트박스 패널**과 가는 형광등 줄을 함께
답니다. 넓은 패널은 강판을 가로지르는 길고 부드러운 그라데이션을, 가는 줄은
날카로운 하이라이트를 만듭니다. 바닥만 어둡게 둬서 비스듬히 볼 때 생기는 어두운
띠를 남깁니다 — 이 세 가지가 같이 있어야 쇠로 보입니다.

**비드를 왜 조각해서 굽는가.** 물결을 셰이더에서 코사인으로 만들면 나사산이
나옵니다. 실제 비드는 초승달이 겹쳐 쌓인 것이고, 각 조각은 뒷날이 가파르고 앞은
완만하며 양 끝(토우)이 중심보다 늦게 굳어 뒤로 휩니다. 이 형상은 수식으로 쓰는
것보다 모델링하는 쪽이 훨씬 쉽고, 모델링하고 나면 물결 사이 골의 그늘도 추측이
아니라 실제로 구울 수 있습니다.

타일은 진행 방향으로 이음매 없이 반복됩니다. 그리고 텍스처를 거리가 아니라
**아크 위상**으로 샘플링하기 때문에, 빨리 움직이면 물결이 늘어나는 성질 — 강사가
보는 바로 그 신호 — 이 그대로 남아 있습니다.

`bake_bead_maps.py`의 타일 상수(`RIPPLES`, `BEAD_HALF`, `HALF_SPAN`)를 바꾸면
`src/WeldBead.js`의 `RIPPLES_PER_TILE`·`BEAD_SPAN_RATIO`도 같이 맞춰야 합니다.

### 아크가 띠는 색

용접 아크는 6000 K 근처라 **차가운 청백색** 빛을 던집니다. 초록빛이 돌면 그건
십중팔구 코드에 박힌 색이 틀린 것입니다 — 실제로 이 데모의 아크광은 오랫동안
`0xcaffdc`(민트색)였고, 용융풀 셰이더의 코어도 초록이 가장 큰 `vec3(2.0, 2.6, 2.0)`
이었습니다.

지금은 세 겹으로 나눠 그립니다: 바깥에 주황색 용융 강재, 그 안에 보랏빛 코로나,
한가운데 1.0을 한참 넘는 값의 플라스마 기둥. 마지막 것이 톤매핑에 의해 흰색으로
날아가면서 가장자리에만 색이 남는데, 그게 실제로 아크를 볼 때 눈에 들어오는
모습입니다.

불똥은 점이 아니라 **자기 속도 방향으로 늘어진 선분**으로 그립니다. 둥근 점은
색종이 조각처럼 보이고, 용접 사진을 용접 사진으로 만드는 건 모든 불똥이 날아간
방향을 가리키는 줄기라는 점입니다. 날아가는 동안 흑체 램프를 따라 흰색 → 노랑 →
주황 → 어두운 빨강으로 식습니다.
